ABSTRACT

The rapid growth of internet-based recruitment has been accompanied by a rise in fraudulent job advertisements that deceive job seekers into paying fake fees or disclosing personal information. This project designed, developed and evaluated an Intelligent Fake Job Advertisement Detection System, a web-based application that automatically classifies job advertisements as genuine or fraudulent using machine learning. The system was developed using an Agile methodology and implemented with Python Flask, Firebase authentication and cloud Firestore database, scikit-learn text classification pipeline as the primary detection model, and an optional bilingual Bidirectional LSTM deep learning model supporting both English and Swahili advertisements. The model was trained on a publicly available dataset of real and fraudulent job postings, with natural language preprocessing performed using NLTK. Key features of the system include user registration and login, advertisement analysis through text entry or PDF upload, bulk checking of job URLs against trusted and suspicious domain lists, prediction history, administrative dashboards with role-based access control, audit logging and English/Swahili language support. Functional testing confirmed that all core modules operated correctly, including PDF text extraction and end-to-end classification of uploaded advertisements. The results demonstrate that machine learning combined with rule-based URL validation can provide practical, low-cost protection for job seekers. It is recommended that future work integrate live scraping of popular job boards, expand the Swahili training corpus and deploy the bilingual deep learning model once sufficient labelled Swahili data is available.

Keywords: fake job advertisement, fraud detection, machine learning, natural language processing, Flask, Firebase.

Chapter One: Introduction

1.1 Background

The Internet has transformed recruitment: organisations advertise vacancies on job boards, company websites and social media, while job seekers apply from anywhere at any time. In Tanzania and across Africa, online recruitment continues to grow as internet penetration increases. Unfortunately, the same channels have attracted fraudsters who post fake job advertisements to extort application fees, harvest personal information, or launder money through bogus “work-from-home” schemes. Victims often lose money and trust, and legitimate employers suffer reputational damage when their names are misused.

Manual inspection of every advertisement is impossible given the volume posted daily, and obvious cues such as unrealistic salaries or requests for payment require experience to recognise. Machine learning, particularly Natural Language Processing (NLP), offers a scalable way to learn deceptive linguistic patterns from historical examples and flag suspicious advertisements automatically before applicants are harmed. This project applies that idea in a practical web system tailored to the Tanzanian context, including support for Swahili-language content and validation of job links against trusted local government and education domains.

1.2 Problem Statement

Job seekers currently have no accessible tool for verifying whether an advertised vacancy is genuine. Fraudulent advertisements circulate freely on social media groups, websites and messaging platforms; they promise high pay for little work, demand upfront “registration” or “training” fees, and collect identity information from desperate applicants. Existing defences rely on individual vigilance or slow manual reporting to authorities, by which time many victims have already lost money. There is therefore a need for an automated, intelligent and easy-to-use system that can analyse a job advertisement — as text, a document or a link — and warn the seeker within seconds whether it shows characteristics of fraud.

1.3 Justification/Significance

  • To job seekers: provides instant, free screening of vacancies before applying or paying any fee.
  • To employers: protects brand reputation by detecting adverts impersonating their organisations.
  • To regulators and institutions: supplies audit logs and statistics that can support anti-fraud campaigns.
  • To academia: demonstrates the applicability of NLP machine learning models, including bilingual (English/Swahili) classification, to a locally relevant problem.

1.4 Aim

The aim of this project is to develop an intelligent, web-based system that detects fake job advertisements using machine learning and rule-based URL validation.

1.5 Specific Objectives

  1. To review literature on fake job advertisement detection and related fraud-detection systems.
  2. To analyse requirements and design the architecture, database and interfaces of the proposed system.
  3. To develop a web application that classifies job advertisements using a trained machine learning model.
  4. To implement supplementary features: PDF upload analysis, bulk job-URL validation, prediction history, role-based administration and bilingual (English/Swahili) support.
  5. To test and evaluate the functionality of the developed system.

1.6 Research Questions

  1. What textual and structural features distinguish fake job advertisements from genuine ones?
  2. How can a machine learning model be integrated into a web application to classify job advertisements in real time?
  3. How effective are domain-reputation rules in complementing machine learning for validating job URLs?

1.7 Scope

The project covers development of a responsive web application with user registration/login, submission of job advertisements by typed text or PDF upload, automatic classification using a supervised text classification model trained on a public dataset of real and fraudulent postings, bulk checking of job URLs against curated trusted/suspicious domain lists, storage of prediction history, and an administrator dashboard for user, permission, domain-rule and audit-log management. Deployment targets a cloud Platform- as-a-Service environment (Render). Detection of non-textual media (images, videos) and integration with third-party job-board APIs are outside the current scope.

1.8 Limitations

  • The training dataset is predominantly English; the Swahili portion of the bilingual model is limited by scarce labelled Swahili job-advertisement data.
  • Sophisticated fraud that perfectly imitates genuine postings may evade text-based detection.
  • Model accuracy depends on the quality and recency of the historical dataset.
  • Free-tier cloud hosting imposes memory limits, which constrained deployment of the deep learning model.

Chapter Two: Literature Review

2.1 Introduction

This chapter reviews the theoretical foundations of employment fraud and text classification, examines related studies and existing solutions, identifies the research gap, and presents the conceptual framework guiding the proposed system.

2.2 Theoretical/Conceptual Background

Routine Activity Theory explains fraud as the convergence of a motivated offender, a suitable target and the absence of a capable guardian. Online job platforms bring offenders and suitable targets (job seekers) together with weak guardianship; this project acts as a technological guardian that screens advertisements before harm occurs.

Deception theory holds that deceptive messages differ measurably from truthful ones — for example, through urgency, vagueness about the employer, and emphasis on money. These differences manifest as lexical and stylistic signals that machine learning classifiers can learn.

Text classification with NLP converts documents into numeric feature vectors. Classical pipelines use bag-of-words or TF-IDF features fed to algorithms such as Naive Bayes, Logistic Regression, Support Vector Machines or SGD-optimised linear classifiers. Deep learning approaches represent words as sequences and use embedding plus recurrent layers such as LSTM — bidirectional variants (BiLSTM) capture context in both directions and perform well on short texts like advertisements.

2.3 Review of Related Studies/Systems

Vidros et al. (2018) built one of the earliest benchmark datasets of real and fake job postings and showed that tree-based and linear classifiers detect fraudulent adverts with high accuracy using textual and metadata features. Subsequent studies confirmed that features such as absence of company profile or logo, requests for sensitive information, and exaggerated salary descriptions are strong fraud indicators.

Kaggle's public “Real/Fake Job Posting Prediction” dataset (approximately 17,880 advertisements, of which about 800, i.e., roughly 4.8%, are fraudulent) has become the standard benchmark; published solutions report accuracies above 90% using ensemble and neural models, though class imbalance requires careful handling.

In the East African context, studies on mobile-money and classified-advertising fraud show that deception increasingly appears in mixed English-Swahili text, motivating multilingual detection. However, few published systems address job-advertisement fraud specifically for the region.

2.4 Existing Solutions

  • Platform moderation (LinkedIn, Indeed): internal teams and automated filters remove flagged posts, but users cannot query arbitrary adverts and moderation is not transparent.
  • Browser safety extensions: block known malicious domains but do not analyse advertisement content.
  • Consumer-protection portals: allow reporting after the fact rather than prevention before application.
  • Academic prototypes: achieve strong offline accuracy but are rarely deployed as usable multi-user web systems with administration, history and localisation features.

2.5 Research Gap

Existing work focuses on offline model accuracy; it seldom delivers a deployed, accessible service for ordinary job seekers. None of the reviewed solutions combines (i) real-time classification via text or PDF, (ii) bulk URL reputation checking tailored to Tanzanian trusted domains, (iii) bilingual English/Swahili support, and (iv) administrative governance with audit trails. This project fills that gap.

Chapter Three: Methodology

3.1 Development Approach

The project adopted the Agile development methodology with iterative increments. Requirements were broken into features (authentication, prediction, history, administration), each implemented, tested and reviewed in short iterations, allowing early feedback and continuous refinement. Model development followed the CRISP-DM cycle: data understanding, preparation, modelling, evaluation and deployment.

3.2 Requirements Analysis

Requirements were gathered through review of fraud reports, inspection of sample fraudulent adverts from social media, and consultation with prospective users (final-year students and job-seeking graduates). Functional requirements include secure registration/login, advert submission by text or PDF, real-time classification with a stated reason, bulk URL checking, personal prediction history, admin management of users/permissions/domain rules, audit logging and language switching (English/Swahili). Non-functional requirements include response time under five seconds per prediction, availability on low-bandwidth mobile connections, role-based security, and scalability through stateless horizontal deployment behind Gunicorn.

3.3 Data Collection Methods

  • Secondary data: the public Kaggle Real/Fake Job Posting Prediction dataset (~17,880 adverts, ~800 fraudulent) was used to train and evaluate the classifier.
  • Observation: collection of example scam adverts circulating on Tanzanian social media to build suspicious keyword and domain lists (e.g., url shorteners, “no experience required” scams).
  • Interviews/consultation: informal discussions with job seekers informed interface and feature design.

3.5 Feasibility Analysis

Technical feasibility: all chosen technologies are open-source, well documented and proven in student projects; the lightweight sklearn pipeline fits free-tier memory constraints after TensorFlow was made optional. Economic feasibility: development used free tools and datasets; hosting uses a free tier, so total cost is minimal. Operational feasibility: the interface requires only basic web skills, matching the literacy of typical job seekers, and supports Swahili for wider accessibility.

3.6 System Architecture

The system follows a three-tier architecture: a presentation tier (responsive HTML/CSS/JS templates), an application tier (Flask routes implementing business logic, session management and model inference), and a data/service tier (Firebase Authentication, Cloud Firestore collections and the persisted ML model).

3.7 Algorithms

Primary model: a scikit-learn Pipeline combining text vectorisation with a regularised linear classifier trained on the labelled dataset; input is a structured record (description, requirements, metadata flags) and output a binary class mapped to fake/legit.

Optional deep model: a Keras Bidirectional LSTM. Text is cleaned (lower-casing, stop-word removal, Porter stemming), words are hashed into a fixed vocabulary (hashing_trick, 5,000 bins) and padded to length 40 before sequence inference.

URL rule engine: each submitted link is parsed; its domain is compared against a trusted set (linkedin.com, indeed.com, government .go.tz/.go.ke, academic .ac.tz/.ac.ke, etc.) and a suspicious set (URL shorteners such as bit.ly, tinyurl.com); combined with HTTPS checks and scam keywords, a risk level of low/medium/high is produced.

Chapter Four: Analysis and Design

4.1 Requirement Specifications

The system must: (FR1) register users with email/password and enforce strong passwords; (FR2) authenticate users and protect all analysis pages with login guards; (FR3) accept an advertisement as typed description plus qualifications, or as a PDF upload, and return a Fake/Legit verdict with a human-readable reason; (FR4) validate one or many job URLs and classify risk by domain reputation; (FR5) persist every prediction with timestamp and user identity for later review; (FR6) restrict administrative functions (users, permissions, domains, audit logs, jobs dashboard) to authorised roles; (FR7) present the interface in English or Swahili. Non-functional requirements cover security (hashed credentials handled by Firebase, server-side session secrets), usability (mobile-first layout), performance (sub-five-second predictions) and reliability (graceful error pages and flash messages).

4.2 System Design

The application is organised as a single Flask package: app.py contains initialisation (Firebase, translations, model loading), route handlers grouped by concern (authentication, prediction, upload, URL checking, history, administration, exports), and helper functions (preprocessing, prediction, PDF splitting, audit logging). Templates inherit from shared header/sidebar partials, ensuring consistent navigation and role-aware menus. Session-based authentication guards privileged routes, and every administrative mutation writes an entry to the audit-log collection.

4.4 User Interface Design

Interfaces were designed mobile-first with a collapsible sidebar. Main screens comprise: Home (service overview), Register/Login/Reset-password, Predict (form with description, qualifications and PDF upload), Bulk URL Check (multi-link textarea with colour-coded results), History (personal records with weekly trend chart), Profile, and Administrator screens (Users, Permissions, Domains, Audit Logs, Jobs dashboard with CSV export). All labels draw from translation dictionaries (en.json/sw.json) enabling instant language switching without page duplication.

Chapter Five: Implementation and Testing

5.1 System Implementation

The system was implemented in Python 3 using Flask, with Firebase Admin SDK handling authentication and Firestore persistence. The trained classifier is serialised with joblib and loaded once at start-up; heavy TensorFlow dependencies were made optional so the production deployment boots quickly within the 512 MB memory limit of the free hosting tier. PDF uploads are parsed with pdfplumber, split heuristically into description and qualification sections, then classified. The application is served by Gunicorn behind Render's edge network, deployed automatically from the GitHub repository, with configuration-as-code (Procfile/nixpacks) ensuring reproducible builds.

5.2 Key Features/Modules

  • Authentication module: registration, login, password reset, session guarding of private pages.
  • Analysis module: text and PDF advert classification with reason generation.
  • URL intelligence module: single/bulk link validation using trusted/suspicious domain sets, HTTPS enforcement and scam-keyword heuristics.
  • History module: per-user prediction records with weekly trend visualisation.
  • Administration module: user management, permission assignment, domain-rule editing, audit logs and jobs dashboard with CSV export.
  • Localisation module: English/Swahili interface dictionaries.

6.2 Discussion of Findings

The results demonstrate that deceptive job advertisements exhibit learnable linguistic signatures — urgency, fee requests, vague employer identity and unrealistic rewards — which the classifier exploits effectively. Rule-based URL validation complements the model: even when advert text looks plausible, links hosted on shortener or unencrypted domains raise risk scores, catching cases pure text models miss. Making TensorFlow optional proved essential for sustainable cloud deployment, illustrating a practical trade-off between deep-learning capability and operational constraints; the sklearn pipeline delivered comparable decisions at a fraction of the resource cost. The bilingual ambition remains partially realised: interface localisation is complete, but Swahili model accuracy awaits larger labelled corpora.

6.3 Conclusion

This project successfully designed, implemented and tested an intelligent web-based system for detecting fake job advertisements. By combining machine learning classification, PDF ingestion, domain-reputation rules and administrative governance in one accessible platform, the system offers job seekers a practical first line of defence against recruitment fraud in Tanzania and beyond. All specified objectives were met within the defined scope.

6.4 Recommendations

  • Collect and annotate Swahili job advertisements to strengthen the bilingual BiLSTM model for production use.
  • Integrate with popular job boards or browser extensions so adverts can be screened where users encounter them.
  • Add explainable-AI highlights (words most influencing a verdict) to increase user trust.
  • Implement periodic model retraining pipelines as new fraud patterns emerge.
  • Upgrade hosting resources to enable always-on deep model serving with autoscaling.
